# ארכיטקטורה ומיפוי רכיבים — מערכת ניהול המשק של גלעם

מסמך זה ממפה את כל רכיבי המערכת, היכן נשמרים הנתונים כיום, ואילו תלויות חיצוניות קיימות.

## 1. רכיבים

| רכיב | מהו | קובץ/מקום |
|------|-----|-----------|
| ממשק הניהול | אפליקציית דפדפן (SPA) בעברית, RTL, PWA הניתנת להתקנה | `index.html` |
| טופס פתיחת קריאת שירות | עמוד עצמאי לפתיחה ולמעקב אחר קריאות | `call.html` |
| Service Worker + PWA | התקנה כאפליקציה, קאשינג, עבודה כשאין רשת | `sw.js`, `manifest.webmanifest`, `icon-*.png` |
| קונפיגורציה בזמן ריצה | כתובת השרת + מפתח ציבורי (anon) — **ללא סודות** | `config.js` (תבנית: `config.example.js`) |
| בסיס נתונים | כל הנתונים היישומיים (11 טבלאות) | כיום: Supabase Postgres |
| צד שרת לוגי | **אין קוד שרת ייעודי.** הדפדפן פונה ישירות ל-REST של Supabase | — |

**חשוב:** אין לפרויקט backend משלו, אין תהליכי שרת, ואין אחסון קבצים. זו אפליקציית צד-לקוח מלאה שמדברת ישירות מול שכבת REST של בסיס הנתונים. אין שימוש ב-Supabase Storage ואין העלאת קבצים כלל.

## 2. היכן נשמרים הנתונים

- **מקור האמת:** בסיס הנתונים (כיום Supabase Postgres, פרויקט `zrmjfxztaeuuvdqhwdzm`). שתי האפליקציות — הניהול וטופס הקריאות — משתמשות **באותו בסיס נתונים מרכזי**. קריאה שנפתחת בטופס נכתבת לטבלת `calls` ומופיעה מיד בלשונית "קריאות פתוחות" בניהול.
- **מטמון מקומי בדפדפן (`localStorage`):** גיבוי-נפילה בלבד. כשאין חיבור לבסיס הנתונים האפליקציה עובדת מול עותק מקומי בדפדפן (מפתח `meshek_live`/דומה) + העדפות (ערכת צבעים, לשונית אחרונה). זהו **אינו** מקור אמת כשהשרת זמין, והוא פר-דפדפן (לא משותף).

### 11 הטבלאות
`items` (פריטים+מלאי+עלות), `departments`, `distributors`, `records` (תנועות חלוקה), `air_conditioners` (מזגנים), `water_devices` (מי שטראוס), `pallets` (משטחים — jsonb), `budgets` (תקציב שנתי), `doors` (דלתות מהירות), `calls` (קריאות שירות — `num` סריאלי למספר כרטיס), `dishwashers` (מדיחי כלים).

## 3. הזדהות והרשאות — מצב נוכחי (פער לסגירה)

כיום אין הזדהות אמיתית: בקוד הדפדפן מוטמע **מפתח anon ציבורי** (JWT), ומדיניות ה-RLS היא `using(true) with check(true)` — כלומר **כל מי שיש לו את הכתובת יכול לקרוא ולכתוב הכול**. זה מתאים לכלי פנימי קטן מאחורי קישור לא-מפורסם, אך **לא** לפריסה ארגונית חשופה. הפתרון המומלץ בפריסה הארגונית: Reverse Proxy עם SSO של Microsoft 365 (Entra ID) לפני כל האפליקציה (ראו `README.md`). המפתח הציבורי אינו סוד ואין בו נזק, אך אין להכניס לקוד הדפדפן אף פעם מפתח `service_role`/אדמין או סיסמת DB.

## 4. תלויות חיצוניות (לטיפול במעבר)

| תלות | שימוש | חלופה בפריסה הארגונית |
|------|-------|----------------------|
| **Supabase** (Postgres + PostgREST + Realtime) | בסיס הנתונים וה-API | Postgres + PostgREST בשרת גלעם (חבילת ה-Docker כאן), או Supabase self-hosted |
| `cdn.jsdelivr.net` → `@supabase/supabase-js@2.39.3` | ספריית הלקוח ל-DB | לוקאלי דרך `vendor/fetch-vendors.sh` |
| `cdnjs.cloudflare.com` → `xlsx@0.18.5` | ייצוא לאקסל | לוקאלי דרך `vendor/fetch-vendors.sh` |
| `fonts.googleapis.com` / `fonts.gstatic.com` | גופנים Assistant + Heebo | לוקאלי (fontsource) או fallback לגופני-מערכת (כבר קיים ב-CSS) |
| `api.open-meteo.com` | תחזית מזג אוויר (קוסמטי) | אופציונלי; מתכווץ בחן אם חסום. אפשר להשאיר/להסיר |

הסרת שלוש התלויות הראשונות הופכת את האפליקציה ל**עצמאית לחלוטין ללא CDN חיצוני** — ראו `README.md` סעיף "הסרת CDN".

## 5. התראות
אין התראות צד-שרת (אימייל/דחיפה). מצב קריאות השירות מנוהל בעמודת `status` בלבד. אם גלעם רוצה התראות — זו תוספת עתידית (למשל webhook/מייל בשרת), לא חלק מהמערכת הקיימת.
