# מסמך ל-IT גלעם — העברת מערכת ניהול המשק לתשתית ארגונית

מסמך קצר לצוות ה-IT: מה המערכת צריכה, ומה עליכם להחליט/לספק כדי להשלים את ההתקנה.
איני מכיר את תשתית ה-GPT הארגונית שלכם — ההנחות למטה פתוחות לכיוונון לפי הסטנדרטים שלכם.

## מה המערכת (בקצרה)
אפליקציית דפדפן סטטית (ניהול המשק + טופס קריאות שירות) מעל בסיס נתונים **PostgreSQL** מרכזי
אחד. אין backend ייעודי ואין אחסון קבצים. חבילת הפריסה (`deploy/`) כוללת Docker Compose
לשלושה שירותים: Postgres, PostgREST (שכבת REST), ו-nginx (הגשת סטטי + reverse-proxy).
פירוט ארכיטקטורה: `ARCHITECTURE.he.md`.

## מה אנחנו צריכים מכם

### סביבת שרת
- [ ] מארח Linux עם **Docker + Docker Compose v2** (או שקילול שווה-ערך בתשתית שלכם:
      Postgres מנוהל + הרצת PostgREST/nginx כקונטיינרים). מה הסטנדרט אצלכם?
- [ ] משאבים מוערכים (עומס פנימי קטן, עשרות משתמשים): **1–2 vCPU, 2 GB RAM, 20 GB דיסק**.
      האם זה מתיישב עם תבנית ה-VM/קונטיינר הארגונית?

### בסיס נתונים
- [ ] PostgreSQL 14+ (נבדק על 16). האם להשתמש ב-Postgres המנוהל שלכם במקום הקונטיינר?
      אם כן — נפנה אליו ב-`PGRST_DB_URI` ונריץ רק PostgREST+nginx.
- [ ] מדיניות גיבוי: סקריפטי `backup.sh`/`restore.sh` מוכנים (pg_dump custom + sha256).
      לשלב ב-cron שלכם, או שתעדיפו גיבוי ברמת ה-Postgres המנוהל?

### רשת, DNS ותעודות
- [ ] שם DNS ארגוני לאפליקציה (למשל `mesek.galam.co.il`) + תעודת TLS.
- [ ] היכן מסתיימת TLS — nginx של האפליקציה, oauth2-proxy, או ה-Load Balancer הארגוני?
- [ ] גישה: פנים-ארגונית בלבד / גם מהנייד (הטכנאים פותחים קריאות מהשטח) / VPN?
      מה המדיניות לגישה מהאינטרנט?

### הזדהות והרשאות (Microsoft 365)
- [ ] האם לאמת מול **Entra ID (M365)** דרך `oauth2-proxy` לפני האפליקציה? אם כן נדרש:
      Tenant ID, App Registration (Client ID + Secret), Redirect URI, והאם להגביל
      לקבוצת אבטחה/דומיין מסוים.
- [ ] האם נדרשת הפרדת הרשאות בתוך האפליקציה (צפייה בלבד מול עריכה)? כיום אין הרשאות
      ברמת האפליקציה — כל המאומתים מקבלים גישה מלאה. אם צריך תפקידים, זו תוספת לתכנן.
- [ ] אישור: המפתח היחיד בצד-הדפדפן הוא מפתח ציבורי (anon) ללא ערך סודי. אין בקוד
      הדפדפן סיסמאות/מפתחות אדמין. סודות (סיסמת DB) נשמרים ב-`.env` בשרת בלבד.

### העברת הנתונים
- [ ] מחרוזת חיבור ישירה ל-Supabase הנוכחי (פורט 5432, תפקיד postgres) לצורך `pg_dump`
      חד-פעמי. ההעברה, בדיקת השלמות, והחזרה מתוארות ב-`MIGRATION-RUNBOOK.he.md`.

## מה כבר נבדק (על PostgreSQL 16, בסביבת הפיתוח)
- טעינת הסכימה (11 טבלאות, תפקיד `web_anon`, RLS) — תקין ואידמפוטנטי.
- פתיחת קריאת שירות → קבלת מספר כרטיס אוטומטי → הופעה בצד הניהול → עדכון סטטוס.
- שרידות הנתונים לאחר הפעלה-מחדש של בסיס הנתונים.
- גיבוי → אסון (מחיקת טבלאות) → שחזור → התאמת ספירות שורות מלאה (שלמות).
- האפליקציה נטענת ומתפקדת ללא תלות ברשת חיצונית (מצב מקומי), וקונפיג הסודות הוחצן מהקוד.

## מה עדיין ממתין לבדיקה בסביבת גלעם
- הרצת מחסנית ה-Docker המלאה מקצה-לקצה (Postgres+PostgREST+nginx) על שרת גלעם
  (בסביבת הפיתוח אין משיכת images מה-registry).
- זרימת ה-SSO של M365 דרך oauth2-proxy (דורש פרטי Tenant/App שלכם).
- TLS/DNS הארגוני וגישה מהנייד.
- העברת הנתונים האמיתית מ-Supabase (דורש מחרוזת חיבור שלכם).
